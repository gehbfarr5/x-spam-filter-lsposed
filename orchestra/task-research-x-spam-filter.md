# 任务：调研 ZPVIP/x-spam-filter 仓库

使用 `github-solution-research` 技能方法论（`gh search`/`gh api`/`gh repo view` 等，
只读，不要修改本仓库任何现有文件），把研究结论写入新文件
`orchestra/research-x-spam-filter.md`（如果该文件已存在就覆盖它）。

## 背景

我们要给官方 X (Twitter) Android App 做一个 LSPosed 模块，实现"按关键词屏蔽推文"，
灵感来自 https://github.com/ZPVIP/x-spam-filter 这个项目，希望复用它整理好的
垃圾/骚扰关键词列表，而不是自己从零攒一份。

## 需要研究的问题

1. **关键词列表位置与格式**：关键词/正则/黑名单具体在仓库哪个文件？是纯文本
   一行一个词，还是 JSON/YAML 结构化数据？是否分类（如按语言、按类型：广告/
   色情/仇恨言论等）？给出文件路径和一段实际内容样例（直接引用，不要转述）。
2. **许可证**：仓库用的什么开源许可证（如果没有 LICENSE 文件也要明确指出）？
   在我们自己的开源项目（LSPosed 模块，计划 public 仓库）里直接复制这份关键词
   列表，法律/署名上需要满足什么条件？
3. **过滤逻辑思路**：该项目自己是怎么用这些关键词做匹配的（浏览器插件/脚本？
   userscript？平台是什么）？有没有值得参考的经验，比如大小写不敏感处理、
   多语言支持、避免误伤正常推文的技巧、正则 vs 精确匹配的取舍？即使我们最终
   在 Android 原生层实现方式完全不同，也要看看它踩过的坑。
4. **可信度与时效性**：仓库最近提交时间、star 数、open issue 情况，关键词列表
   多久更新一次，是否有"关键词过时/误报"类的 issue 讨论，帮助我们判断这份列表
   拿来直接用是否可靠。

## 输出要求

- 直接引用具体文件路径/代码行/issue 链接作为证据，不要凭空转述或猜测。
- 关键词列表如果体量不大（几十到几百条），把它完整摘录或列出获取方式
  （例如"raw 文件 URL"），方便我们后续直接下载固化到本地。如果体量很大，
  给出统计信息（条数、分类）+ 前 30-50 条样例即可，并说明如何拿到完整列表。
- 如果某项证据不足，如实说"证据不足/未找到"，不要编造。
- 篇幅够用即可，突出结论和可执行信息（文件路径、URL、许可证类型），不需要写成大论文。
